# TRON2 真机接入路线

真机后端仍在规划中，当前仓库可以运行 Mock 和 MuJoCo。建议先在 S1、S2 验证相同的任务脚本，再按本页的顺序接入设备。[仿真运行与验收](tron2_bringup.md) · [高层工具契约](tron2_architecture.md#工具和坐标约定)

## 接入边界

计划在 `capx/envs/simulators/tron2_real.py` 提供真机环境，由独立运动服务适配 `Tron2Backend`。CaP-X 侧保留任务和高层工具。真机服务负责运动规划与控制器调用、夹爪反馈、限位和故障处理。LimX 的 `tron2_env` 提供 WebSocket 运动传输和相机观测入口，现场需核对具体机型、末端组件和观测模式。[LimX 真机运行时](https://github.com/limxdynamics/tron2_env)

现有 CaP-X 执行器会在本进程运行生成的 Python，只适合可信仿真。真机评测需隔离代码执行环境，让机器人侧仅接收允许的高层动作，在受控局域网内部署。运动服务应承担失联或超时停止、急停联锁和人工复位，且独立于 Agent 的判断。[厂商运行安全说明](https://github.com/limxdynamics/tron2_env#safety-notes)

## 验收顺序

1. **校准与观测。** 确认机型、双臂关节方向和限位、夹爪开合与力反馈。校准 `robot_base`、TCP、相机内参和手眼外参，核对采样时间与状态时间，验证头部和腕部运动后坐标变换仍一致。
2. **空载与故障测试。** 在有人监督的工作区检查低速短动作、工作空间、碰撞保护、急停、失联超时和人工复位。确认设备侧速度、关节和力限值后再放置物体。
3. **先跑真机 Oracle。** 让固定脚本依次完成 Cube Lift 和 Pick & Place。根据实际观测确认稳定夹持和释放，记录重复试验的完成数、掉落和碰撞等失败原因。
4. **再做真机 Agent 评测。** Oracle 重复执行通过后，在现场监督下启用受限工具，保存每次执行的代码、工具结果、关节状态、RGB-D、错误和耗时。连续录像与状态同步仍需接入。

仿真结果用于验证任务和软件流程。真机验收需要本机标定数据、设备安全检查和现场试验记录。
